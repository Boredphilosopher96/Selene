# Enterprise persona journeys and capability ledger

This is an operator guide for the pre-alpha Selene product. It separates a
portable contract or automated gate from a journey that an independent person
has actually completed. Read it with the
[usability verification playbook](../quality/usability-verification-playbook.md):
the playbook describes how to collect the independent evidence that this guide
does not manufacture.

## Evidence and status rules

Every statement in the capability ledger uses exactly one of these statuses:

- **Independently verified** — a role-appropriate person completed the exact
  journey in an immutable desktop build, deployment, or handoff and attached a
  public-safe evidence packet. Source, CI, PR review, and a screenshot alone
  do not qualify.
- **Automated-only** — a portable contract, source test, or CI workflow is the
  available evidence. It is useful engineering evidence, not an operator
  acceptance claim.
- **Planned/blocked** — no appropriate independent evidence exists, or the
  required product surface or host deployment is not available. Do not present
  it as a usable product capability.

The exact source snapshot for the links below is
[`b2a3b9c`](https://github.com/Boredphilosopher96/Selene/tree/b2a3b9c2696fa5adb5788d21ecb59652f9dad0fd).
These are reproducible source and workflow references, not proof that a
customer host is configured. The public acceptance backlog is tracked in the
[persona-validation issue](https://github.com/Boredphilosopher96/Selene/issues/44),
the [designer-workspace issue](https://github.com/Boredphilosopher96/Selene/issues/41),
and the [direct-manipulation editor issue](https://github.com/Boredphilosopher96/Selene/issues/38).

## Common identity, provenance, and recovery rules

Before any role starts, record an immutable project/revision identity and the
input provenance that the host exposes: design-system package/version, design
language location, actor or agent identity, and evidence/checksum references.
The portable design-input contract preserves provider, location, and retrieval
metadata; inspect the exact input rather than copying a label into a review
note. See the [design-input source contract](https://github.com/Boredphilosopher96/Selene/blob/b2a3b9c2696fa5adb5788d21ecb59652f9dad0fd/packages/design-inputs/src/index.ts)
and the [federation/handoff contract](https://github.com/Boredphilosopher96/Selene/blob/b2a3b9c2696fa5adb5788d21ecb59652f9dad0fd/docs/federation.md).

If a revision, provenance record, baseline, artifact checksum, identity
assertion, or recovery path is absent or contradictory, stop that journey:

1. Preserve the immutable revision, visible error, and non-secret evidence.
2. Do not substitute a fixture, fallback account, mutable URL, or guessed
   revision.
3. Return to the owning host/operator with the failed identity and the next
   safe action. A retry must name the same immutable starting point or a
   clearly newer one.

For shared review, a dropped event stream recovers from the durable cursor
endpoint rather than timestamps; a host must keep identity verification and
authorization server-side. Those are contract requirements, documented in the
[collaboration service guide](https://github.com/Boredphilosopher96/Selene/blob/b2a3b9c2696fa5adb5788d21ecb59652f9dad0fd/docs/collaboration.md),
not evidence of a deployed collaboration tenant.
